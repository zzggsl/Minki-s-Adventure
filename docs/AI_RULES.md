# AI 협업 규칙 (AI Collaboration Rules)

1. **상태 보존**: 기존 기능을 삭제하거나 동작 방식을 변경하는 경우, 반드시 이유와 영향 범위를 먼저 설명하고 사용자의 승인을 받은 후 진행할 것.
2. **이유 있는 변경**: 파일 이동이나 구조 변경 시 반드시 그 이유와 기대 효과를 사전에 설명할 것.
3. **변경 목록 보고**: 작업 후에는 반드시 수정된 파일의 목록과 핵심 변경 사항을 요약할 것.
4. **리팩터링 우선순위**: 기능 추가가 급한 경우 '기술 부채'를 인정하고, 리팩터링은 기능 안정화 후에 수행할 것.
5. **엄격한 타입**: TypeScript에서 `any` 사용을 금지하며, 인터페이스(`interface`)를 통해 명확한 타입을 정의할 것.
6. **계획 먼저, 코드 나중**: 복잡한 기능을 추가하기 전, Gemini는 반드시 '변경 계획'을 제시하고 사용자의 동의를 얻을 것.
7. **기존 코드 스타일 유지**: 새로운 파일이나 코드를 추가할 때 기존 프로젝트의 네이밍 규칙, 폴더 구조, 코딩 스타일을 최대한 유지할 것.
8. **TODO 갱신**: 작업 완료 후 docs/TODO.md를 함께 갱신하여 완료된 항목과 앞으로 해야 할 작업을 반영할 것.
